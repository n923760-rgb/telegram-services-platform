# Deterministic PDF page utilities

Baseline: official main `27d67a6` after template/gate PR #24. Its reviewed head
workflow `37917138383` passed 406 tests, lint/format, migrations/drift and Compose.
Local baseline tree matches main exactly (`18e13f436eddfe7f790f564bcd2924e6de6ccf37`).

## Scope

New independently discovered `pdf_tools` plugin, disabled by default, SAR 2.00
administrator-issued test credit. Merge two to five PDFs or extract pages from
one PDF in the explicitly requested order (example `3,1-2`). Arabic digits and
commas supported; duplicates, reversed ranges and nonexistent pages rejected.
No AI calls; use the existing pypdf dependency rather than duplicate it with qpdf.

Preserve source page text, images, dimensions and rotation without OCR/rasterizing.
Copying pages does not retain document outlines or metadata. Forms/signatures
are unsupported and rejected at the document root. Do not advertise this as a
general PDF editor, signature-preserving workflow or document sanitization.

Bounds: five files, 10 MiB each, 20 MiB total, 200 total source pages and 10 MiB
generated output. Strict PDF parse and existing generated-output gate required.
Encrypted/unreadable input fails without output. Pure input validation rejects
cross-field mistakes before reservation; file-content failures release credit.

Registry/intake menus discover the plugin; no bot, core, ledger, jobs, worker,
runtime settings, dependencies or migrations changed. Arabic/English prompts and
safe error keys included. Operator enablement and real Telegram acceptance remain
separate from source merge.
