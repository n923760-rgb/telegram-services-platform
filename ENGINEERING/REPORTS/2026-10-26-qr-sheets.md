# Static QR sheets

Baseline: main e8c97d6b9b2b4984c9aee011a7fd9aafd17237e0.
Owner requests continued development of the approved service expansion.

## Implemented

- qr_codes v1, Arabic/English intake and order-review labels, default disabled.
  One to 24 source rows in one request; six vector symbols per A4 PDF page.
  Customer label at most 40 characters; literal payload at most 240 UTF-8 bytes.
  Duplicate payloads, leading zeros, Unicode and spaces remain literal.
- Existing ReportLab QR implementation, error correction M and four-module quiet
  zone. No dependencies, external calls, models or remote resources.
- Generic discovery/intake/worker/storage/result flow; no bot or core service branch.
  Initial default price 3 SAR; existing administrator prices remain authoritative.
- Strict row/byte/control bounds before reservation. No blank rows or implicit
  trimming of payloads. Delimiter splits only once, retaining later pipes.
- Single PDF artifact avoids multi-file partial-save cleanup. Existing failure
  release and prepared-result delivery semantics remain authoritative.
- Add qr_sheet to isolated acceptance (31 cases, 18 customer services).
  Add DB capture/release/re-execution tests and network-disabled non-root worker
  read-back qualification to hosted CI. Extend portfolio assertions.

## Evidence and limits

- PASS: 193 focused tests including all 18 QR checks and presentation/acceptance
  regressions. PDF rasterization plus OpenCV QRCodeDetectorAruco independently
  decodes exact payloads for single Arabic/English, mixed seven-row pagination and
  all 24 symbols in four-page batch, in source order.
- PASS: visual inspection of every page of the four-page Arabic batch; symbols,
  labels and page numbers stay within pages with clear separation.
- PASS: three architecture gate functions, global lint, format and diff checks.
- The ordinary OpenCV detector missed one valid synthetic symbol; ArUco-based
  independent decoding succeeds on the same PDF. This does not qualify every
  camera/scanner. No downstream phone/printed scan evidence is available.
- BROAD LOCAL RUN: 1475 passed, six failures require /usr/bin/libreoffice, which
  is absent in this runtime. These six failures are in unchanged Word/CV/Excel
  rendering tests, not QR checks. Rerunning Word table/CV layout files with the
  existing LOCAL_WORD_PDF_TEST_BINARY override passes all 14 checks (including
  the four affected Word/CV cases). Two Excel print checks still require the
  unavailable hard-coded /usr/bin/libreoffice path.
- NOT RUN locally: PostgreSQL lifecycle, migrations/drift or Docker worker image;
  those capabilities are unavailable here. Hosted full checks required.
- NOT RUN: actual Telegram/mobile order journey or printed scans; production
  activation/deployment. No claim of all-service launch readiness.
