# بوت الخدمات الرقمية — التشغيل والحوكمة

الأساس يدعم إضافة خدمات تدريجيًا من مجلدات مستقلة. القائمة، جمع المدخلات والاختيارات
تُولّد من تعريف الخدمة؛ لا تحتاج إلى إضافة اسمها إلى كود البوت أو المحفظة أو العامل.

الخدمات الحالية: استخراج النص من الصور مع ترجمة اختيارية، وتحويل النص إلى Word أو Excel.
توجد خدمة echo للاختبار، ومكوّنات مشتركة لبناء Word وExcel وPowerPoint وPDF.

## التشغيل الأول باستخدام Docker

تحتاج إلى Docker مع Compose وPython 3.12. من مجلد المشروع:

```bash
python scripts/configure.py
docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:8000/health
```

البرنامج الأول يطلب توكن Telegram بشكل مخفي وأرقام المستخدمين المسؤولين. ينشئ `.env`
بصلاحيات خاصة وكلمة مرور عشوائية ومتطابقة لقاعدة البيانات. لا يستبدل ملفًا موجودًا.
اكتب الأسرار على جهاز التشغيل، ولا تضعها في GitHub أو المحادثات أو لقطات الشاشة.

ابدأ محادثة مع البوت باستخدام `/start`. يستطيع المسؤول إضافة رصيد تجريبي:

```text
/addbalance USER_ID 20
```

اختر خدمة echo للتأكد من المسار الكامل. خدمات الذكاء الاصطناعي معطلة افتراضيًا؛ فعّلها بعد
إضافة مفتاح المزود، النموذج وأسعاره الصحيحة في `.env` وتعيين `AI_ENABLED=true` وإعادة تشغيل
الخدمات. الأوامر الإدارية:

```text
/enable image_to_text
/enable text_to_office
/setprice text_to_office 5
```

## إضافة خدمة جديدة

1. أنشئ `app/services/<slug>/` وفيه `schema.py` و`prompt.py` و`service.py` و`test_service.py` و`__init__.py`.
2. ورّث `BaseService` وحدد السعر، الإصدار، النصوص ونموذج المدخلات؛ صدّر `SERVICE`.
3. استخدم واجهة الذكاء الاصطناعي والتخزين المعزول الخاص بالعميل ومكوّنات بناء الملفات.
4. أضف نصوص العربية والإنجليزية، واختبارات النجاح والفشل مع إعادة الرصيد المحجوز.
5. أعد التشغيل للمزامنة ثم فعّل الخدمة. تغييرات عقد المدخلات تتطلب رفع إصدارها؛ الأسعار
   وحالة التفعيل التي عدّلها المسؤول تبقى محفوظة.

## ملف الحوكمة والاختبارات

`AGENTS.md` يحدد قواعد المال، الأمان، حدود الطبقات، طريقة إضافة الخدمات وأوامر التحقق.
الاختبارات المعمارية تمنع استيراد Telegram والعملاء الشبكيين داخل الخدمات، وتتحقق من عدم
وجود أسماء خدمات محددة في النواة. ملف GitHub Actions جاهز لفحوص المراجعة عند رفع المشروع.

مرجع صيغة الملف هو مستودع AGENTS.md العام. راجعت النسخة المثبتة من مستودع
`n923760-rgb/engineering-governance` وكيّفت قواعده مع المشروع؛ المصدر وحدود التكييف في
`docs/GOVERNANCE.md`. خريطة العمل الوحيدة في `ENGINEERING/MASTER_ROADMAP.md`، وتقارير
المراجعة والأدلة في المجلدين المجاورين لها. `PROJECT-SOURCES.md` يربط الملفات الأساسية.

استخدم قاعدة بيانات منفصلة تنتهي باسم `_test` لتشغيل الاختبارات؛ الاختبارات تمسح جداولها.
راجع `README.md` لإعداد بيئة الاختبار والتشغيل المحلي و`docs/OPERATIONS.md` للنسخ الاحتياطي
والاستعادة و`docs/VALIDATION.md` لنتائج التحقق وحدوده.

رصيد الريال في هذه النسخة تجريبي يُصدره المسؤول. البيع الفعلي للخدمات الرقمية داخل Telegram
يتطلب تصميم دفع متوافقًا باستخدام Stars؛ بوابات الدفع خارج نطاق هذا المشروع.
