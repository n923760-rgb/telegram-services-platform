# بوت الخدمات الرقمية — التشغيل والحوكمة

الأساس يدعم إضافة خدمات تدريجيًا من مجلدات مستقلة. القائمة، جمع المدخلات والاختيارات
تُولّد من تعريف الخدمة؛ لا تحتاج إلى إضافة اسمها إلى كود البوت أو المحفظة أو العامل.

الخدمات الحالية: استخراج النص من الصور مع ترجمة اختيارية، وتحويل النص إلى Word أو Excel،
وإنشاء عروض PowerPoint احترافية، وإنشاء مستندات PDF قابلة للطباعة. توجد خدمة echo للاختبار، ومكوّنات مشتركة لبناء Word وExcel وPowerPoint وPDF.

## التشغيل الأول باستخدام Docker

تحتاج إلى Docker مع Compose وPython 3.12. من مجلد المشروع:

```bash
python scripts/configure.py
docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:8000/health
```

البرنامج الأول يطلب توكن Telegram بشكل مخفي وأرقام المستخدمين المسؤولين. ينشئ `.env`
بصلاحيات خاصة وكلمة مرور عشوائية ومتطابقة لقاعدة البيانات. لا يستبدل ملفًا موجودًا.
اكتب الأسرار على جهاز التشغيل، ولا تضعها في GitHub أو المحادثات أو لقطات الشاشة.

ابدأ محادثة مع البوت باستخدام `/start`. يستطيع المسؤول إضافة رصيد تجريبي:

```text
/addbalance USER_ID 20
```

اختر خدمة echo للتأكد من المسار الكامل. خدمات المستندات وOCR معطلة افتراضيًا.
يمكن تفعيل Word وPDF للتحويل المباشر دون إعداد مزود؛ المسار الذكي وExcel وبقية خدمات AI تتطلب
إضافة مفتاح المزود، النموذج وأسعاره الصحيحة في `.env` وتعيين `AI_ENABLED=true` وإعادة تشغيل
الخدمات. الأوامر الإدارية:

```text
/enable image_to_text
/enable text_to_office
/enable text_to_pptx
/enable text_to_pdf
/setprice text_to_office 5
```

## إعداد المستندات والتحويل المباشر

في Word يكفي إرسال المحتوى واختيار Word؛ لا سؤال إضافي عن الطريقة أو العنوان.

- **نقل Word حرفيًا دون AI:** اكتب «بدون تعديل النص» في السطر الأول ثم المحتوى في الأسطر
  التالية. تُحذف عبارة الطلب وحدها من الملف، ويحفظ المحتوى والمسافات والأسطر دون عنوان مولّد.
  لا تتغير الطريقة إذا وردت العبارة داخل النص. يدعم السطر الأول أيضًا Keep text unchanged
  ونقطتين اختياريتين في نهايته. النص الفارغ بعد العبارة يُرفض قبل الحجز.
- **تحويل PDF مباشر دون AI:** يبقى اختيارًا صريحًا مع عنوان اختياري أو زر «بدون عنوان»؛ يحفظ الكلمات والأرقام
  والأسطر الفارغة، لكنه يعيد التفاف السطور ويوحّد مسافات العرض؛ ليس إعادة إنتاج لتخطيط أصلي.
- **إعداد مستند Word احترافي تلقائيًا:** يقترح AI عنوانًا مختصرًا دون سؤال إلزامي، وينظم
  المحتوى وفق المهمة إلى أقسام وفقرات وقوائم وجداول قابلة للتحرير عند الحاجة، ثم ينسقه الكود.
  الملاحظات القصيرة لا تتحول إلى تقارير طويلة مصطنعة. الجداول تدعم العربية والإنجليزية،
  وتكرر رؤوسها عبر الصفحات؛ الحد 6 أعمدة و100 صف للجدول و240 حرفًا للخلية و10 جداول للمستند.
  التعليمات تمنع اختراع الحقائق وتحافظ على الأرقام والتواريخ، لكن صحة المحتوى تحتاج مراجعة
  مخرجات المزود الفعلي؛ التحقق من البنية وحده لا يثبتها. لا تشمل صورًا أو رسومًا أو هوية مخصصة.
- **تنظيم PDF بالذكاء الاصطناعي:** يحتفظ بمسار الخطة المتحقق منها وموافقة العميل عند الغموض.
  Excel ما زال يستخدم هذا المسار فقط؛ لا تحويل مباشر له في هذه الدفعة.

السعر المعروض واحد للطريقتين ولا يتغير تلقائيًا؛ عدم استخدام مزود ليس إلغاءً لسعر الخدمة.
يبقى الحجز والتسليم والتسوية وحذف الملفات كما هو، وتظل حدود القبول العامة مطبقة.
إصدار Word/Excel أصبح 5، ويبقى PDF بالإصدار 3؛ المسودات القديمة تحتاج بدء الخدمة مجددًا، والطلبات القديمة
غير المتوافقة وغير المجهزة تُلغى مع تحرير الحجز. النتائج المجهزة يعاد تسليمها دون توليد جديد.

## واجهة العميل ومتابعة الطلبات

تظهر قائمة سفلية ثابتة بعمودين: الخدمات، طلباتي، رصيدي، الدعم، اللغة والمساعدة.
تُحفظ مسودة الإدخال أثناء التنقل أو فتح الدعم أو إرسال `/start` مجددًا. يعيد زر
«متابعة المسودة» السؤال الحالي، وتغيير اللغة يحدّث القائمة والسؤال دون فقد المدخلات.
اختيار خدمة يبدأ مسودة جديدة؛ زر الإلغاء متاح في كل خطوة ولا يحجز رصيدًا.
مسودات Redis مؤقتة وتنتهي بعد ساعة من آخر تحديث للحالة/البيانات.

«طلباتي» يعرض الطلبات الأحدث أولًا على صفحات، مع الحالة والتكلفة وتاريخ الإنشاء
بتوقيت السعودية. يمكن تحديث الحالة، ومن التفاصيل اعتماد أو رفض الهيكل إذا كان الطلب
ينتظر موافقة العميل. السجل يقتصر على صاحب الطلب، ولا يعيد تنزيل الملفات المحذوفة.

أوامر العميل: `/menu`، `/services`، `/orders`، `/wallet`، `/help`، `/lang`،
`/support`، `/resume` و`/cancel`. يبقى `/balance USER_ID` أمرًا إداريًا.
أسماء أزرار القائمة في اللغتين محجوزة للتنقل، ولا تُستهلك كمدخلات خدمة أو رسائل دعم.

## إضافة خدمة جديدة

1. أنشئ `app/services/<slug>/` وفيه `schema.py` و`prompt.py` و`service.py` و`test_service.py` و`__init__.py`.
2. ورّث `BaseService` وحدد السعر، الإصدار، النصوص ونموذج المدخلات؛ صدّر `SERVICE`.
3. استخدم واجهة الذكاء الاصطناعي والتخزين المعزول الخاص بالعميل ومكوّنات بناء الملفات.
4. أضف نصوص العربية والإنجليزية، واختبارات النجاح والفشل مع إعادة الرصيد المحجوز.
5. أعد التشغيل للمزامنة ثم فعّل الخدمة. تغييرات عقد المدخلات تتطلب رفع إصدارها؛ الأسعار
   وحالة التفعيل التي عدّلها المسؤول تبقى محفوظة.

## ملف الحوكمة والاختبارات

`AGENTS.md` يحدد قواعد المال، الأمان، حدود الطبقات، طريقة إضافة الخدمات وأوامر التحقق.
الاختبارات المعمارية تمنع استيراد Telegram والعملاء الشبكيين داخل الخدمات، وتتحقق من عدم
وجود أسماء خدمات محددة في النواة. ملف GitHub Actions جاهز لفحوص المراجعة عند رفع المشروع.

مرجع صيغة الملف هو مستودع AGENTS.md العام. راجعت النسخة المثبتة من مستودع
`n923760-rgb/engineering-governance` وكيّفت قواعده مع المشروع؛ المصدر وحدود التكييف في
`docs/GOVERNANCE.md`. خريطة العمل الوحيدة في `ENGINEERING/MASTER_ROADMAP.md`، وتقارير
المراجعة والأدلة في المجلدين المجاورين لها. `PROJECT-SOURCES.md` يربط الملفات الأساسية.

استخدم قاعدة بيانات منفصلة تنتهي باسم `_test` لتشغيل الاختبارات؛ الاختبارات تمسح جداولها.
راجع `README.md` لإعداد بيئة الاختبار والتشغيل المحلي و`docs/OPERATIONS.md` للنسخ الاحتياطي
والاستعادة و`docs/VALIDATION.md` لنتائج التحقق وحدوده.

رصيد الريال في هذه النسخة تجريبي يُصدره المسؤول. البيع الفعلي للخدمات الرقمية داخل Telegram
يتطلب تصميم دفع متوافقًا باستخدام Stars؛ بوابات الدفع خارج نطاق هذا المشروع.
